# one-net：一份总账，喂饱多个 AI

一个人同时用好几个 AI 助手时，最累的不是 AI，是人——同一件事要说三遍，还得自己在几个 AI 之间传话、盯着谁欠什么没办。

**one-net** 是一套让多个 AI 助手共用一份总账的协议：一份人能读、AI 也能读的 Markdown 文档，助手开工前先读它，临时状态写在状态栏里，处理完留回执。一张网，多个 AI：学习、生活、项目几摊活记在一份总账里，对一个助手说一遍，其他都知道，不再当 AI 之间的传话筒。

## 两个仓库，分工明确

- **这个公开仓库**只放协议、模板和工具——就是你现在看到的这些文件，任何人可以照着搭自己的一套。
- **你自己的真总账**放在你自己的**私有仓库**里，永不公开。公开仓库里永远不出现任何人的真实数据。

## 三个助手，三摊活（以我自己的用法为例）

- **规划助手**：排期和进度——每天做什么、欠账记账与跟进
- **贴身助手**（手机/手表上）：健康、生活账本、随手记与陪练
- **项目助手**（电脑端，兼任书记员）：项目管理、定时推送、定期复盘，以及总账的统一并账

你有几个助手、分几摊活，都可以照这个结构改。

## 核心设计

1. **单一事实来源**：所有状态只存一份总账，谁需要谁来读，用户只说一遍。
2. **分开写、合并读**：每个来源文件只有一个写入方，合并成一份 `LEDGER.md` 给助手读，状态栏排最前。细则见 `PROTOCOL.md`。
3. **书记员制度**：只有一个助手（书记员）能写仓库，其他助手只投递——用预填 Issue 链接或经用户转交。出了问题只查一个地方。
4. **口令握手**：总账第一行是每次更新都换的随机口令。助手回复时先报口令，报得出才证明它真的读了最新文件。
5. **状态栏 + 回执**：临时事项写成结构化条目（带到期时间），排计划的助手读到后顺延，并回写具体结果——回执就是原先要靠用户亲口转达的那句话。
6. **按读者暴露**：封闭平台的助手只能读到单独发布的脱敏片段（一般只有今日状态和它自己那一节）；生活线和钱永不进任何链接片段。
7. **红线**：账号、密码、验证码、密钥绝不进库；花钱决策要用户本人确认。细则见 `PROTOCOL.md`。

## 快速开始

十分钟就能搭好，只需要三步：

1. **建私有仓库，复制模板**：新建一个只有你自己能看的仓库，把 `knowledge-base-template.md` 复制进去、改名为 `knowledge-base.md`（拆分版布局见 `PROTOCOL.md` 第一节），把尖括号占位符换成你自己的内容。不确定怎么填，先看 `example/knowledge-base.example.md` 的完整示例（虚构人物，仅供参考）。
2. **填好你的总账**：先填「用户速览」和「分工」两节，再给每个助手分一节它维护的状态；选一个电脑端助手当书记员。填不全没关系，先跑起来，边用边补。
3. **交给你的每个 AI 助手**：把总账链接（或给它的只读片段链接）发给每个助手，同时把 `PROTOCOL.md` 里的「给你的 AI 的开工指令」复制粘贴给它，把占位符换成这个助手的角色和它负责的那一节。

之后你只管对任何一个助手说话，它会按规矩投递给书记员并账；其他助手下次开工读一遍，就都知道了。建议按 `PLAN.md` 的三周节奏落地：先手工跑通，再逐周自动化。

## 文件

- `README.md` — 本文件，项目说明
- `PROTOCOL.md` — 运行规矩 v2：布局与书记员、开工先读与口令握手、状态条目与回执规范、按读者暴露与隐私指南、绝对时间、Issue 回写通道、红线，附可直接复制的开工指令
- `PLAN.md` — 三周落地清单：从单文件手工版到拆分自动版的分周步骤与验收标准
- `knowledge-base-template.md` — 总账模板，复制到你的私有仓库后填入你自己的内容
- `example/knowledge-base.example.md` — 填好的完整示例（虚构人物「小林」），照着它填最省事

**隐私说明**：公开仓库只放模板和虚构示例，不放任何人的真实数据。我本人填好的那份总账在自己的私有仓库里，不在本仓库。你也一样：填好的总账请只放在私有位置，不要提交到公开仓库。

## 路线图

- **第 1 周（当前）**：单文件总账 + 结构化状态条目 + 口令握手，纯手工跑通。
- **第 2 周**：预填 Issue 回写通道上线，书记员每天定时处理收件箱，缺回执自动升级提醒。
- **第 3 周**：拆分来源文件，脚本/Action 自动拼接合并视图、轮换口令，并按读者自动生成脱敏片段。
- **之后**：先自己用满 4 周（每天维护不超过 5 分钟）再谈正式推广；协议太重就先改轻。分周细节见 `PLAN.md`。

## 背景

市面上的 AI 共享记忆产品（Mem0、supermemory、Basic Memory 等）大多是给开发者用的向量数据库，人读不了、也管不了「谁负责哪一摊」；而「状态栏＋回执顺延」这种让助手之间互相转接的机制，目前没有产品实现。这里先用最土的办法跑通：一份 Markdown ＋ 一套规矩，再按路线图慢慢补齐自动化。
